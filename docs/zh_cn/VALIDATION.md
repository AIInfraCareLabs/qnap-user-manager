## 真实写入与分页验证（2026-11-26）

设备：TS-873 / QTS 5.1.9.2954 build 20241120，与随包 profile 精确匹配。测试用户、组和共享目录均由测试创建并删除；未修改任何既有数据。最终基线：3 个用户、3 个组、2 个共享目录。

- 标准 live regression（在移除成员读取分页参数前执行）：24 项检查全部通过并带写后回读（CRUD、成员变更、共享属性、密码重置、禁用/启用、用户/组权限）；`baseline_restored=true`，`cleanup_errors=[]`。
- 成员：一个组内创建 11 个测试用户后，`groups.members` 与 `Group.members()` 返回全部 11 个。`lower`/`upper` 不会对成员字符串分页。结构化 `userroot` 候选用户目录在 `upper=1/10/100` 时分别返回 1/10/14 条。11 人组的成员添加/移除成功。已从 profile 和两个 SDK 成员读取方法中移除这些被忽略的分页参数。修改后的最小真机检查使用 2 人组，成员读取、添加/移除及清理通过，基线恢复。
- 共享目录：创建 11 个测试共享目录；连同原有 2 个，`shares.list` 不传 `lower`/`upper` 时返回 `count=13`、13 条记录，SDK 也返回 13 条。该接口同时接受 `[lower, upper)`（原有 2 个时 `upper=1` 返回 1 条）。随包 profile 现已声明 `lower`/`upper`，`Shares.list_all()` 会分页，离线测试覆盖分页边界；13 条以上的默认上限仍未确定，但 `list_all()` 不再依赖它。
- 清理：连续快速删除用户时，NAS 的 `fork_del` 路径可能静默忽略部分请求。SDK 会报告未确认删除而不会误报成功；间隔删除并延长回读超时后完成清理。live 清理脚本应间隔删除用户并核对列表。
- 在 QTS 5.2.11.3683 上的只读浏览器会话交叉验证复现了成员行为（`ownUser` 全量、`userroot` 分页），并显示 `users.list` 遵守 `upper`；dashboard 原先只请求第一页，现已改用 `list_all()`。该交叉验证不构成对该固件的兼容性声明。
